# 从零开始学习开发个人智能体

这是一篇阶段性的学习记录，记录我开始了解 Agent 智能体和大模型开发之后的思考。现在还没有完成一个真正可用的个人智能体，所以这篇文章不会把计划写成已经实现的功能，而是先记录为什么开始、目前的理解，以及接下来准备如何实践。

## 为什么想学习个人智能体

我平时会接触很多技术资料，也会记录一些学习过程和项目想法。资料刚开始接触时通常很零散，可能来自文章、视频、代码仓库或临时的聊天记录。过一段时间再回头看，经常只能记住结论，却想不起当时为什么这样理解。

我想尝试开发一个属于自己的智能体，最初的目的并不是做一个复杂的平台，而是解决几个具体问题：让它能够阅读我的学习笔记，帮助我回顾技术内容，把零散的想法整理成结构化记录，并在需要时辅助生成博客文章的大纲。

## 我目前对智能体的理解

在我现在的理解里，普通聊天主要是用户提出问题，模型根据当前上下文生成回答。智能体则需要在模型之外增加一些可以执行的能力，例如读取资料、调用工具、保存结果，或者根据任务决定下一步动作。

因此，智能体不只是“接入了大模型的聊天页面”。一个比较简单的智能体流程通常还包括：

- 理解用户的目标
- 判断是否需要使用工具
- 获取和整理外部信息
- 根据结果继续处理任务
- 输出可以被人检查和使用的结果

这也意味着，开发智能体时不能只关注模型回答得像不像，还要关注资料来源、工具权限、执行过程和最终结果是否可靠。

## 我想先解决的问题

第一版个人智能体不准备覆盖太多场景，先围绕学习和写作做一个小范围尝试：

1. 根据问题检索本地 Markdown 技术笔记。
2. 基于检索到的内容解释概念，并保留参考来源。
3. 将一次学习过程整理成知识点总结。
4. 根据项目记录生成博客文章大纲。
5. 输出 Markdown 或 MDX 草稿，由我人工检查后再发布。

这里特意保留人工确认环节。技术文章涉及事实、代码和个人判断，不能因为模型生成了内容，就直接把它当成最终结果。

## 准备采用的学习路线

我准备按照由简单到复杂的顺序学习，而不是一开始就搭建多智能体系统。

### 先理解大模型的基本调用

第一步是熟悉模型调用、提示词、上下文、结构化输出和错误处理。只有先了解这些基础能力，后面才容易判断问题到底来自模型、提示词还是程序逻辑。

### 再学习工具调用

接下来学习如何让模型调用有限的工具，例如搜索本地文件、读取指定文章、保存一份草稿。工具需要有明确的输入和输出，也要限制访问范围，不能让模型拥有不必要的系统权限。

### 然后尝试知识库检索

当笔记数量增加后，仅依赖上下文直接塞入全部内容并不现实。这时可以学习向量检索或其他搜索方式，让程序先找到相关笔记，再把必要的内容交给模型处理。

### 最后组合成可用工作流

等前面的部分都能单独运行后，再把问题识别、资料检索、总结和草稿生成组合起来。第一版更像一个有明确步骤的工作流，而不是完全自主运行的系统。

## 第一版可能的结构

我目前设想的最小流程如下：

```text
用户输入问题
  ↓
判断任务类型
  ↓
检索本地 Markdown 笔记
  ↓
整理相关内容并交给模型
  ↓
生成回答、总结或文章大纲
  ↓
人工确认并保存
```

这个结构暂时不包含自动发布、复杂记忆、多智能体协作和高权限电脑操作。先让每一步都能被理解、测试和调整，比追求“看起来很智能”更重要。

## 我准备如何记录学习过程

后续每次学习或实践，我会尽量记录以下内容：

- 这次想解决什么问题
- 之前是怎么理解的
- 尝试了什么方案
- 实际结果是什么
- 遇到了什么问题
- 下一步准备验证什么

这样记录的好处是，文章不只留下最终结论，也能保留理解变化和失败过程。对我自己来说，这些过程往往比一份整理得很完整的最终教程更有参考价值。

## 当前阶段

目前我还处在确定方向和整理学习路线的阶段，尚未完成个人智能体的实际开发。接下来会先从模型调用和本地笔记检索开始，逐步验证这个方向是否真正适合自己的学习和写作流程。

实践过程中，如果发现某个想法没有实际价值，也会及时缩小范围，而不是为了增加功能继续堆叠复杂度。

## 后续计划

后续会继续记录以下内容：

1. 第一次调用大模型 API 的过程。
2. 如何设计一个简单可靠的工具调用接口。
3. 如何检索本地 Markdown 笔记。
4. 如何让模型基于来源生成回答。
5. 如何把项目实践整理成博客文章。

等第一版实践项目真正开始后，再单独写一篇带代码的实现文章，把项目结构、核心代码、问题和改进过程记录下来。

## 总结

开发个人智能体对我来说，重点不只是完成一个功能，而是通过这个过程理解大模型如何与资料、工具和实际任务结合。现在的想法还比较初步，后续会用实际开发结果来验证它，而不是提前假设所有设计都正确。

这篇文章会随着学习和实践继续更新。
