# 个人技术博客 MVP 总体方案设计

## 1. 核心总体方案

采用静态站点优先、构建时全量生成架构。系统以 MDX 内容文件和配置文件作为主要数据源，Next.js 在构建阶段完成内容解析、字段校验、页面生成、索引构建和 SEO 资源输出，最终产出可部署到静态托管平台的站点。

系统不依赖后端服务。核心内容在构建阶段生成，主题切换、客户端搜索、复制代码、回到顶部等少量体验能力在浏览器端执行。

## 2. 五层精简架构

### 2.1 内容层

数据来源：

- 技术文章：`content/posts/*.mdx`
- 项目数据：配置文件
- 站点信息：配置文件
- 作者信息：配置文件
- 导航、页脚、社交链接、备案预留位：配置文件

生活随笔预留：

- MVP 不强制拆独立目录。
- 文章模型预留 `type` 或 `category`，后续可承载生活随笔。
- 当随笔内容规模扩大后，再评估是否拆分为独立目录和独立频道。

### 2.2 内容处理层

构建时统一处理：

- 解析 MDX Frontmatter。
- 校验必填字段和核心配置，关键字段缺失时阻断构建。
- 根据环境处理草稿：开发环境可展示，生产环境过滤。
- 归一化分类和标签：单分类、多标签、标签去重。
- 自动计算阅读时长。
- 使用 Frontmatter 中的 `excerpt` 作为摘要；`excerpt` 在 MVP 中为必填字段，缺失时阻断构建。
- 生成上一篇/下一篇关系。
- 生成文章列表数据、分类索引、标签索引。
- 生成客户端搜索索引。索引只包含列表和搜索所需字段，不包含完整正文，避免静态资源体积失控。

### 2.3 页面呈现层

页面入口：

- 首页：个人定位、精选文章、最新文章、精选项目。
- 文章列表页：时间倒序、分页、分类/标签筛选、关键词搜索。
- 文章详情页：MDX 渲染、TOC、阅读时间、发布/更新时间、上下篇跳转。
- 分类总览页：展示全部分类及文章数量。
- 分类详情页：按分类浏览文章，支持分页。
- 标签总览页：展示全部标签及文章数量。
- 标签详情页：按标签浏览文章，支持分页。
- 关于页：个人介绍、技能栈、联系方式。
- 项目页：配置化展示精选项目和全部项目列表，不做项目详情页。

### 2.4 体验增强层

基础体验：

- 主题系统：默认跟随系统，支持手动切换，本地持久化偏好。
- 代码块：语法高亮、行号、复制按钮、移动端横向滚动。
- 搜索体验：客户端关键词搜索、命中高亮、无结果空状态。
- 阅读体验：TOC、回到顶部、图片加载优化。
- 适配体验：全站响应式，兼容桌面端和移动端。
- 可访问性：图片要求提供 Alt 文案，交互控件具备可识别状态。

### 2.5 发布层

构建和部署：

- 构建阶段生成静态页面。
- 构建阶段将 RSS、Sitemap、`robots.txt` 输出为静态文件。
- 页面输出 TDK、Open Graph、Canonical 等 SEO meta 信息。
- 输出静态产物，优先支持 Vercel / Cloudflare Pages。
- GitHub Pages 作为兼容部署目标，需要遵守静态导出限制。

部署约束：

- MVP 不依赖 SSR。
- 不依赖 API Routes。
- 不依赖 Server Actions。
- 不依赖常驻后端服务。
- 图片优化策略需兼容静态部署环境。

## 3. 核心数据流

```text
MDX 文章 / 配置文件
→ Frontmatter 校验
→ 草稿环境过滤
→ 内容归一化处理
→ 生成页面数据、分类索引、标签索引、搜索索引
→ 生成静态页面、RSS 静态文件、Sitemap 静态文件、robots 静态文件
→ 静态托管部署上线
```

## 4. 关键设计决策

- 内容基于 MDX，而不是数据库，保证轻量、易维护、Git 可追溯。
- 全站业务数据配置化，避免页面组件硬编码。
- 内容结构统一为单分类、多标签。
- MVP 使用客户端本地搜索，避免后端搜索依赖。
- `/posts` 是全量文章浏览入口，负责分页、分类筛选、标签筛选和关键词搜索；`/categories`、`/tags` 是总览入口，详情页负责按分类或标签浏览。
- SEO 和订阅资源在构建阶段生成。
- 评论、统计、后台、CMS 等能力作为外部扩展点，不进入 MVP。
- 架构保留扩展方向，但不提前引入复杂依赖。

## 5. MVP 严格边界

MVP 包含：

- MDX 写作和浏览。
- 文章列表、详情、分类、标签。
- 筛选、搜索、分页。
- 分类总览、标签总览。
- 主题切换。
- 响应式体验。
- 基础 SEO。
- RSS。
- 静态部署。
- Frontmatter 校验。
- 草稿环境隔离。
- 项目页、关于页。

MVP 不包含：

- 后台管理。
- 用户系统。
- 评论。
- 访问统计。
- 媒体上传或媒体库。
- 项目详情页。
- 复杂 i18n。
- Mermaid。
- 数学公式。
- 时间线归档。
- 友链。
- 点赞、收藏、分享计数。
- Headless CMS。

## 6. 四阶段迭代路线

阶段 1：MVP 落地

- 完成写作、浏览、搜索、主题、SEO、RSS、部署闭环。

阶段 2：内容体验增强

- 接入 Mermaid、数学公式、时间线归档、友链、分享优化等内容增强能力。

阶段 3：互动增长

- 外置接入评论、访问统计、订阅增强、站内推荐等能力。

阶段 4：产品化管理

- 在兼容现有 MDX 数据源的前提下，接入 Headless CMS 或自研后台发布能力。
