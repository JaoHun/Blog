# 个人技术博客 MVP 需求文档

## 1. 核心定位

建设一个轻量化静态个人技术博客，优先满足稳定持续写技术笔记、沉淀知识、展示个人技术品牌的需求，同时为未来生活随笔内容预留空间。

第一阶段目标是可直接上线、低维护、可持续写作、可渐进式扩展。系统不以完整内容平台为目标，不引入后台、用户、评论、统计等动态复杂能力。

核心原则：

- 只做上线刚需功能。
- 内容文件化，配置集中化。
- 静态优先，避免后端依赖。
- 高阶能力后置迭代。
- 架构预留扩展，但 MVP 不提前实现复杂功能。

## 2. MVP 包含范围

### 2.1 页面模块

- 首页：个人定位简介、精选文章、最新文章、精选项目入口。
- 文章列表页：时间倒序、分页、分类/标签筛选、客户端关键词搜索，支持搜索高亮和无结果空状态。
- 文章详情页：MDX 渲染、代码高亮、行号、复制代码、TOC 目录、阅读时间、发布/更新时间、上下篇跳转、图片加载优化。
- 分类总览页：展示全部分类及对应文章数量。
- 分类详情页：按单一主分类浏览文章，支持分页。
- 标签总览页：展示全部标签及对应文章数量。
- 标签详情页：按标签浏览文章，支持分页。
- 关于我：个人介绍、技能栈、联系方式。
- 项目页：通过配置展示精选项目和全部项目列表，不做独立项目详情页。

### 2.2 基础系统能力

- 主题系统：默认跟随系统明暗模式，支持手动切换，用户选择本地持久化。
- 草稿机制：开发环境可展示草稿，生产环境过滤草稿。
- 内容规范：统一文章 Frontmatter 元数据，支持精选、置顶、自定义摘要、封面图。
- 站点配置：导航、页脚、版权、备案预留位、社交链接等通过配置文件维护，不在页面中硬编码。
- 配置校验：构建时校验站点、作者、导航、项目等配置文件，避免缺失关键配置导致页面异常。
- 内容校验：构建时校验必要 Frontmatter 字段，避免内容错误导致页面异常。

### 2.3 SEO 与订阅

- 基础页面 TDK。
- 文章页 Open Graph 社交分享标签。
- Canonical 链接。
- 构建时静态生成 `robots.txt`。
- 构建时静态生成 Sitemap。
- 构建时静态生成全站 RSS。
- 图片要求提供有意义的 `alt` 文案。

### 2.4 通用体验

- 全站响应式，适配桌面端和移动端。
- 代码块在移动端支持横向滚动。
- 提供回到顶部按钮。
- 图片加载体验优化。
- 文章页面重点保证阅读体验和代码可读性。

### 2.5 上线配套

- 优先适配 Vercel / Cloudflare Pages 等静态托管平台。
- GitHub Pages 作为兼容目标，需要遵守静态导出限制。
- 第一版不依赖常驻后端服务。

## 3. MVP 明确不做

- 后台管理。
- 评论系统。
- 访问统计。
- 用户系统。
- 媒体上传或媒体库。
- 项目详情页。
- 复杂多语言切换。
- Mermaid。
- 数学公式。
- 时间线归档页。
- 友链。
- 点赞、收藏、分享计数。
- Headless CMS 对接。

## 4. 核心内容规范

文章 Frontmatter 建议字段：

```yaml
title: string
date: string
updated?: string
excerpt: string
category: string
tags: string[]
featured?: boolean
sticky?: boolean
draft?: boolean
cover?: string
slug?: string
type?: "tech" | "essay"
```

字段规则：

- `title`、`date`、`excerpt`、`category`、`tags` 为必填。
- `updated` 为可选更新时间字段；项目内所有更新时间字段统一使用该命名。
- `category` 为单一主分类。
- `tags` 支持多个，并在构建时自动去重。
- `draft: true` 的文章仅开发环境展示。
- `featured` 用于首页精选文章。
- `sticky` 用于文章列表置顶。
- `cover` 可选，不强制每篇文章都有封面。
- `slug` 可选；未提供时由文件名生成。
- `type` 用于预留内容类型，MVP 默认以技术文章为主，后续可承载生活随笔。

## 5. 环境规则

开发环境：

- 展示草稿文章。
- 支持本地实时预览。
- 内容校验给出明确错误提示。

生产环境：

- 过滤草稿文章。
- 搜索索引、RSS、Sitemap 均排除草稿。
- 构建产物可直接部署到静态托管平台。

## 6. 数据与搜索规则

以下信息必须配置化，不在组件中硬编码：

- 站点名称。
- 站点描述。
- 作者信息。
- 顶部导航。
- 页脚信息。
- 社交链接。
- 备案预留位。
- 项目列表。
- 首页精选内容。

配置文件必须在构建时校验：

- 站点配置必须包含站点名称、描述、站点 URL、默认 Open Graph 图片。
- 作者配置必须包含名称、简介和至少一种联系方式或社交链接。
- 导航配置必须包含可访问路径，禁止指向未生成页面。
- 项目配置必须包含项目名称、简介、技术栈和状态；外链字段可选但必须是合法 URL。

搜索索引规则：

- 搜索索引字段包含 `slug`、`title`、`excerpt`、`category`、`tags`、`date`、`updated`、`type`。
- MVP 不把完整正文写入搜索索引，避免静态资源体积过大。
- 搜索索引只包含生产可见文章，必须排除草稿。
- 搜索索引建议以 JSON 静态文件输出，并尽量控制在 200 KB 以内；超过该体积时应评估分片、压缩或升级搜索方案。

## 7. 远期预留扩展

后续可按阶段扩展：

- 第三方评论，如 Giscus。
- 轻量统计，如 Umami、Vercel Analytics 或 Cloudflare Web Analytics。
- 多语言。
- Mermaid。
- 数学公式。
- 友链。
- 项目详情页。
- 自动化图床。
- Headless CMS。
- 文章分享增强。
- 点赞、收藏。
- 时间线归档页。

## 8. 上线交付可测试清单

第一版完成后必须通过以下检查：

- 本地执行内容校验命令时，Frontmatter 与配置文件校验通过。
- 新增一篇非草稿 MDX 文章后，首页、文章列表、文章详情、分类详情、标签详情、搜索索引、RSS、Sitemap 均能包含该文章。
- 新增一篇 `draft: true` 文章后，开发环境可见，生产构建产物、RSS、Sitemap、搜索索引均不可见。
- `/posts` 支持分页、分类筛选、标签筛选、关键词搜索、搜索高亮和无结果空状态。
- `/categories` 和 `/tags` 总览页可访问，并显示对应条目数量。
- 文章详情页显示代码高亮、行号、复制按钮、TOC、阅读时间、发布/更新时间、上下篇跳转。
- 浅色、深色、跟随系统三种主题路径可用，手动切换后能本地持久化。
- `robots.txt`、`sitemap.xml`、`rss.xml` 可作为静态文件访问，且不包含草稿文章。
- 基础 SEO 信息存在：页面 title、description、canonical、Open Graph。
- 桌面端和移动端页面无明显布局溢出，代码块可横向滚动。
- 构建产物可部署到 Vercel 或 Cloudflare Pages；如选择 GitHub Pages，必须通过静态导出配置验证。
- 实现内容不包含 MVP 明确排除的后台、评论、统计、用户系统等功能。
